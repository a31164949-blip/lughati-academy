# نشر عضوية ضيوف التحديات والمسابقات

هذه الميزة في الفرع `feature/external-grade-join-requests-20261119`. **لا تدمج أو تنشر إلى خادم الإنتاج قبل استكمال فحوصات الأمان والبناء.**

## نطاق العضوية
- طلب انضمام مستقل لا ينشئ مستندًا في `students` ولا حساب Firebase للضيف.
- المعلم يقبل أو يرفض الطلب، وعند القبول يُصدر رمز دعوة سري يُعرض مرة واحدة فقط.
- الدخول إلى `/guest-competitions` بجلسة HMAC لمدة ساعتين تحفظ داخل حالة صفحة الضيف فقط.
- API الضيف المسموح: `/api/guest-competition` والتحدي المباشر `/api/academy-club/live-game` فقط.
- كل طلب API يتحقق من استمرار الموافقة في مستند `externalGradeJoinRequests`؛ إلغاء القبول يوقف الجلسة.
- قواعد Firestore وطرق دخول الطلاب الحالية **لم تُعدّل**.

## المتغيرات اللازمة في خادم الإنتاج
- `NEXT_PUBLIC_TURNSTILE_SITE_KEY` (مفتاح عام لاسم نطاق الأكاديمية).
- `TURNSTILE_SECRET_KEY` (مفتاح سري على الخادم فقط).
- `COMPETITION_GUEST_SESSION_SECRET` (سر عشوائي قوي لا يقل عن 32 حرفًا؛ لا تنشره في GitHub).

قبل النشر تحقق أن نطاق الموقع مضاف لخدمة Cloudflare Turnstile وأن تسجيل الضيف وطلب العضوية يعملان من متصفح حقيقي. لا تُرسل أي مفاتيح سرية في المحادثة.

## خطوات تحقق آمنة على VPS
1. احفظ نسخة احتياطية من بيئة الخادم، وسجل نسخة commit الحالية، وتحقق من نظافة شجرة Git: `cd /opt/lughati/lughati-next && git status --short && git rev-parse HEAD`.
2. اجلب التعديلات من GitHub إلى فرع اختبار (لا تُسقط تعديلات محلية): `git fetch origin feature/external-grade-join-requests-20261119`.
3. اختبر داخل نسخة منفصلة أو worktree. تثبيت الاعتمادات باستخدام `npm ci` ثم `npx tsc --noEmit` ثم `npx eslint app/api/external-grade-join/route.ts app/api/competition-guest-login/route.ts app/api/guest-competition/route.ts app/api/academy-club/live-game/route.ts app/components/ExternalGradeJoinCard.tsx app/components/GuestLiveChallenge.tsx app/guest-competitions/page.tsx app/teacher/external-join/page.tsx`.
4. **لا تشغّل `npm run build` دون مراجعة**: هذا السكربت ينفذ `scripts/deploy-temporary-access-rules.cjs` قبل Next.js وقد يعدل قواعد Firebase المباشرة. لبناء Next.js فقط استخدم `npx next build` في بيئة اختبار مضبوطة.
5. اختبر طلب الضيف، قبول المعلم، صدور رمز الدعوة، دخول الضيف، تسجيل إجابات المسابقة، غرفة التحدي المباشر، الصوت والنقاط، رفض الدخول إلى واجهات وAPIs الطلاب والبيانات الخاصة، وإلغاء العضوية خلال الجلسة.
6. تحقّق من قيود تكاليف Firestore قبل فتح عضويات كثيرة: استعلام المعلم يقرأ 30 مستندًا كحد أقصى لكل تحديث يدوي. دخول الضيف يقرأ مستند العضوية؛ وكل تحديث للتحدي المباشر (كل 25 ثانية عندما تكون الصفحة مرئية) يقرأ العضوية والغرفة. لا تُفعّل تحديات كثيرة بالتزامن دون قياس التكلفة.
7. بعد النجاح فقط، خطط الدمج والنشر مع نقطة تراجع. راقب `journalctl -u lughati.service` واختبر الموقع بعد إعادة تشغيل الخدمة.

## ملاحظات أمنية
- رموز الدعوات سرية، أرسل لكل ولي أمر رسالته بصورة فردية، ولا تسجل الرموز في سجلات الخادم.
- Cloudflare Turnstile يقلل الروبوتات لكنه لا يضمن حدًا يوميًا لكل IP؛ أضف حدّ معدل على Nginx أو خدمة مماثلة قبل الإطلاق العام.
- رفع الصوت في التحدي المباشر يستخدم خدمة Cloudinary الموجودة في مشروع الطلاب؛ تحقق من حصة الرفع وسياسة حفظ الصوت مع ولي الأمر قبل بدء أول تحدٍ.
- التحدي المباشر يعرض أسماء المشاركين ونقاطهم للمشاركين في الغرفة. تحقق من موافقة ولي الأمر على الاسم المعروض.
